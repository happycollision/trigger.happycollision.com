# In Ear

A static, interactive listening lab for singers learning in-ear monitor routing, served from `public/in-ear/` at `/in-ear/`. Use the site's `npm start` for development or `npm run build` and `npm run preview` for the production build. No app dependencies, backend, microphone permission, or account required. Run `npm test` from the repository root for routing contract tests.

Trigger is a personal lyrics tool, mostly used by Don's wife, not a promotional site. All three tracks are retained for that personal/noncommercial use. Reassess the two noncommercial licenses before any commercial reuse; personal use is not a blanket licensing exemption.

The root service worker excludes all of `/in-ear/` from precaching and from its homepage navigation fallback. The listening lab requires a connection; it does not promise offline playback. Opening the lyrics tool never downloads the music. No separate service worker is registered by In Ear. The existing lyrics pages retain their offline behavior.

Imported from the source thread's local, uncommitted app using `in-ear-handoff.tar.gz` (SHA256 `8db543a6d82dcc7dfc793bddb3dd5612849a2a938bc28edce50bf4055c7e06cc`). Runtime files and assets are preserved unchanged; the routing test import and this documentation are adapted to the host repository.

Four setups model a shared monitor bus, a direct mic split through a preamp, an independent pre-fader aux, and a two-input “me + band” personal mixer. Instead of channel faders, singers request presets from the simulated engineer: original balance, more voice, or less drums. Presets replace rather than accumulate. The comparison toggle auditions the shared stage-monitor signal, not simulated room acoustics. Local ear level never changes the stage-monitor signal.

The personal mixer receives only a direct vocal and a band-only aux (excluding that vocal to prevent duplication). Its device-style panel has two continuous, keyboard-accessible vertical faders: My voice and Band feed. Each runs from silent to full level; the band fader preserves the relative instrument balance. Less drums still requires an engineer request, which changes that dedicated band feed without changing the shared stage monitor. Real multichannel personal systems exist, but this lesson does not assume those extra channels are available.

The equipment diagrams use locally bundled, AI-generated unbranded product illustrations in `assets/`, with SVG cables and radio links. They preserve physical locations: the singer’s mic, earphones, bodypack, and wedge are together on stage, while cables run to and from the sound desk. The stage wedge is a separate line-level branch, never a speaker-power feed to the transmitter. Equipment and socket positions are representative, not model-specific connection instructions. Narrow screens can scroll the diagram horizontally, including with the keyboard.

The song selector offers 40-second practice remixes of **“Making Me Nervous” by Brad Sucks** (CC BY 2.5), **“So Silent” by Wiseman featuring Zara Merinen** (female-vocal atmospheric downtempo), and **“My Time” by Wiseman** (soul). Both Wiseman songs are **CC BY-NC 4.0: noncommercial use only**; obtain permission or replace those assets before commercial use. These are edited excerpts, not original full album mixes. Attribution, source links, and preparation details are in [CREDITS.md](../../public/in-ear/assets/audio/CREDITS.md) and linked in the player.

Each song has four locally bundled MP3 stems (about 2.5 MB per song), loaded only on Play: voice, accompaniment (the internal `guitar` slot), bass, and drums. All stems decode before playback starts and share one start time and 40-second loop boundary. Changes use smoothed gains; pause retains position; a failed load can be retried. Switching songs stops playback, resets the position, and releases the previous buffers; wiring and mix presets stay unchanged. The selector is disabled while loading to prevent overlapping loads. No music is generated or separated by AI. Google Fonts is optional; system fonts are the fallback.

Output starts conservatively, but device gain is outside the app’s control. This is not a hearing-safety tool or a physical wiring manual. Real microphones require compatible splits/preamps, and earphones require a headphone amp or IEM receiver, never a powered speaker output.
